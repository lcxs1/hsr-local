## 2. 协议链（4.6.54）

```text
GetChallengeCsReq            -> 843 条（MOC 639 / PF 112 / AS 92）
GetChallengeGroupStatistics  -> 对应 group 的统计 oneof（必填！见 §5）
EnterSceneCsReq(100000104)   -> 进入忘却之庭大厅（plane 10000 / floor 10000000）
StartChallengeCsReq(id)      -> scene + cur_challenge + lineup，session 进入挑战
SceneCastSkillCsReq          -> monster_battle_info(TRIGGER_BATTLE) + SceneBattleInfo
PVEBattleResultCsReq         -> ScRsp + ChallengeSettleNotify（星数/FINISH）
LeaveChallengeCsReq          -> 回到进入挑战前的场景（大厅/世界）
```

关键点：

- 战斗关卡 id = `EventIDList1/2` 里的 event id（如 `30309011`、`420101`、`30501011`），
  在 `StageConfig.json` 里能查到 `Level` + `MonsterList`（波次）。
- `rounds_limit`：PF = 4，其余 = 30。
- `cur_challenge.stage_info` 用 union：
  - PF → `cur_story_buffs`（`ChallengeStoryBuffList`，buff = `MazeBuffID` + 玩家选择 buff）
  - AS → `cur_boss_buffs`（`ChallengeBossBuffList`，`challenge_boss_const=1`）
- `battle_target_info`（`SceneBattleInfo`）：
  - PF：slot1 = `10002`（stage < 30309011）或 `10003`；slot5 = `2001/2002`
  - AS：slot1 = `90005`
- 挑战场景：`MapEntranceID → PlaneID/FloorID`，`MazeGroupID → 场景实体组`，
  `NpcMonsterIDList/EventIDList → 该组里那只 NPC 怪`；出生点用 `Anchor.json` 的 `entryID`。
- 场景实体坐标来自 `res.json`（932 个场景）；本项目已导出需要的子集到 `data/endgame.json`。

## 5. 真机记录与坑

| 现象 | 根因 | 修复 |
|---|---|---|
| 指导「传送」完全没反应 | 只处理固定世界；客户端发 `EnterSceneCsReq(100000104)` 被忽略 | 按 `MapEntrance` 切场景 + `EnterSceneScRsp`/`EnterSceneByServerScNotify` |
| 传送后加载条卡死，`Player.log` 报 `MapNPC:227-400001` NRE | `GetChallengeGroupStatisticsScRsp` 只回 `retcode+group_id`，客户端 `ChallengeGroupStatisticsData.Create` 解引用空统计 → 异常污染后续流程 | 填满 `challenge_default/story/boss` oneof（level/buff/lineup） |
| 打完回场景、怪重生、无限循环 | 没有 `ChallengeSettleNotify`，客户端不知道这局已结束 | 结算时发 `ChallengeSettleNotify(is_win, star=3, cur_challenge.status=FINISH)` |
| 结算后直接掉回初始世界（20313） | `LeaveChallenge` 固定回世界 | 记录进入挑战前的场景，退出时回该场景 |
| **打完不回结算、回场景怪物重生、无限循环（2026-11-11 复现）** | 客户端在 arena 加载期间反复发 `SceneCastSkill`（一局 8 次），`battle_info()` 每次都分配新 `battle_id`；真结算回的是旧 id（`battle result id 6 does not match active battle 8`），`owns_battle` 为假 → 不发 `ChallengeSettleNotify` | `battle_info()` 复用已激活战斗（幂等）；`ChallengeState.battle_ids` 记录本次挑战分配过的全部 id，`on_pve_result` 按集合判定归属 |
| **忘却之庭大厅只有两个默认关卡组（2026-11-11）** | 指导「传送」进的是 plane 10000（列车车厢），`data/endgame.json` 没有该 plane 数据，`enter_scene` 走普通世界装配 → 只发角色组 + 凝滞虚影组 | 新增 `lobby` 数据段（plane 10000 的 17 个 entry/道具），`enter_scene` 按 entry 生成 `extra_groups`，`SceneMapInfo` 上报真实组与道具 |
| **打完上半直接整局结束、没有「前往下半」** | `on_pve_result` 对任何胜利都立刻发 `ChallengeSettleNotify` | 新增 `can_advance`/`advance_stage`：有 node2 且还在上半时加载下半场景 + `ChallengeLineupNotify(LineupChallenge2)` + 场景切换，下半打完才结算（对齐 DanhengServer `AdvanceStage`） |
| **下半还是上半的队伍（2026-11-11 第二轮真机）** | `StartChallengeCsReq` 里 `avatar_lineup_first`/`avatar_lineup_second` 都有，`on_start_challenge` 只取第一套 | `ChallengeState.first_avatars/second_avatars` 都保存；`advance_stage` 换成第二套；客户端只带第二套重发 `StartChallengeCsReq` 时（pearl-sr 分支）直接进下半，不清状态 |
| **打完停在列车车厢，出不去（2026-11-11）** | 大厅是在 `EnterSceneCsReq` 里从世界切过去的，`LeaveChallenge` 记录的是大厅 | 进入大厅时把「来之前的世界场景」记到 `session.lobby_return`，`LeaveChallenge` 优先生效（对齐 pearl-sr 直接回世界场景） |
| **再点一次「传送」没反应（2026-11-11）** | `on_enter_scene` 里 `entry_id == state.entry_id` 直接回空 `EnterSceneScRsp`，不发场景 | 同 entry 重新装配并下发 `EnterSceneScRsp` + `EnterSceneByServerScNotify` |
| **下半进战斗黑屏（2026-11-11 第三轮）** | `SceneBattleInfo.monster_wave_length`（字段 7，混淆名 `JAOIOKBBMFC`）一直没填；客户端 `Player.log` 报 `battleAreaDef 失败`、战斗场景初始化失败 | 按波次数填该字段（对照 pearl-sr `createBattleInfo`）；**该错误已消失，但下半仍黑屏并自行结算**（见 §6） |
| **忘却之庭关卡组卡片缺失（2026-11-11 第三轮）** | `GetChallengeScRsp` 只发 `challenge_list`，卡片所需的 `challenge_group_list` 为空 | 每个挑战组补一条 `ChallengeGroup(group_id, taken_stars_count_reward=0)`；待真机复测 |


已真机验证的完整链路：

```text
指导 → 传送 (EnterScene 100000104)
 → 大厅点水晶 (StartChallenge id=15, stage=30001151)
 → 放技能打怪 (SceneCastSkill, waves=2, avatars=4, buffs=10)
 → PVEBattleResult WIN → ChallengeSettleNotify（星数/轮次页）
 → LeaveChallenge → 回到大厅（2026-11-10 晚用户确认）
```

遗留瑕疵：

1. 「传送」偶发卡加载：`Player.log` 报 `AdventurePhase._EnterStep2` 加载
   `MapNPC:227-400001` 时 NRE（`MapNpcDef.ConfigEntityPath` 为 null），重启/重试可恢复；
   服务端日志正常，暂判为客户端地图 NPC 资源问题。
2. 挑战面板显示“满进度”：`star=7` / `taken_reward=42` 是 pearl 的写法，
   不是真实通关记录；组统计 `level` 取该组最大层。
3. 结算星数固定 3、无奖励、无 `max_level`。

## 6. 下一步

**2026-11-11 收尾后的四件实事（按优先级）**

1. **下半黑屏（最高优先）**：`battleAreaDef` 失败已随 `monster_wave_length` 消失，但客户端
   仍不渲染可操作战斗，约 16 s 后自己回 `PVEBattleResult WIN` 并结算。下一轮要在客户端
   `Player.log` 里只盯那 16 s（`SceneCastSkillScRsp` 之后到 `PVEBattleResult`）的阶段性错误，
   对照上半成功那局的日志差异；可疑项还有 `battle_avatar_list` 用第二队时的
   `LineupChallenge2` 一致性、`SceneMonsterWave.battle_stage_id`（pearl 没填，存疑）。
2. **忘却之庭右侧缺「物竞天择」卡**：已确认卡片不是 `challenge_group_list` 驱动
   （本轮发 109 个组仍只有 2 张卡）。卡片由客户端按自身轮换配置渲染，缺的是"当前轮换组"
   对应的挑战数据，需要在 4.6.54 资源里定位该组 id（`ChallengeMazeConfig` 里按
   主题/轮换时间筛），再补进 `data/endgame.json`。
3. **PF / AS 锁定且点开空白**：现状是 `challenge_list` 全量假 `star=7 / taken_reward=42`，
   项目没有任何通关历史。参考实现（pearl-sr `AddHistory`、DanhengServer `ChallengeManager`）
   都是持久化历史 + 结算写入 + 组数据更新。按 [AGENTS §2](../../AGENTS.md)：改存档直接做，
   只有删除/覆盖无法重建的存档才先问一句。
4. **丹恒腾荒技能释放失败**：用户已同意搁置；复测时记录"哪个技能/什么提示/在哪个界面"。

其余旧项（Peak、网页 `battle_config`、结算 UI、传送卡加载）保持不变：

1. **Peak**：10 条 CsReq + 2 条 Notify + 困难模式 + 结算；数据已就绪。
