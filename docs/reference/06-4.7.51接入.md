## 8. 2026-11-13 真机排查：**4.7.51 是 4.8 beta，协议整体重排**

首登失败的表象是「服务器连接错误：请检查网络状态，关闭网络代理，重启游戏再次尝试」，
但服务端日志里 **SDK / dispatch / gateway 全部 200，之后没有任何 UDP 包**。

### 8.1 根因：GateServer 字段号变了

用 ppSR 4.7.5X（同一客户端可正常进游戏）的 `/query_gateway` 响应做通用 protobuf wire 解析，
4.7.51 的 `GateServer` 与 4.6.54 的 pb2 **不是同一套字段号**：

| 字段 | 4.6.54（本项目 pb2） | 4.7.51（ppSR 实测） |
|---|---:|---:|
| `ip` | 3 | **15** |
| `port` | 9 | **5** |
| `ex_resource_url` | 5 | **8** |
| `asset_bundle_url` | 6 | **13** |
| `lua_url` | 7 | **9** |
| `asset_bundle_url_b` | 1379 | **1507** |
| `ifix_url` | 694 | **1895** |
| `ifix_version` | 1286 | **1988** |
| `lua_version`（`mdk_res_version`） | 1516 | **2011** |
| 8 个 bool | 10/15/77/454/802/918/1559/1975 | 6/14/247/410/809/984/1140/1293 |

客户端按自己的字段号解析，读不到 ip/port → 根本不发 UDP。**不是 Clash/代理问题**
（同一台机器、同一代理，ppSR 能进）。

### 8.2 修完 gateway 后已经走到哪一步

- 新增 `hsr/dispatch/gateway_wire.py`：4.7.51 专用手写 `GateServer` 线格式；
  `query_gateway` 在该 profile 下改回这份字节。
- 真机结果（2026-11-13 17:50）：
  - 客户端拉完 `/cdn` 清单（200）；
  - **UDP 握手成功**：`client ('127.0.0.1', 64245) connected: mode=u32_le_token ...`；
  - 第一条 C→S 是 **cmd 73**（`PlayerGetTokenCsReq`，26 B），服务端记 `UNKNOWN_73`。
- 结论：**传输层（握手 / KCP / 帧）与 4.7.51 兼容**，卡在命令号与消息字段号。

### 9.2 实现：descriptor 快照 + 字段名适配 + partial cmd 表

1. **快照加载**：[hsr/protocol/dynpb.py](../../hsr/protocol/dynpb.py) 用私有 `DescriptorPool`
   从 `classes.desc` 建消息类。生成的 `StarRail_pb2` 不能和 4.6.54 同进程 import：
   两者消息同名，protobuf 默认池会报 duplicate symbol；私有池没有这个问题。
2. **取类入口**：handler 原来 `from hsr.protocol.gen import StarRail_pb2 as pb`，现在统一
   `from hsr.protocol import pb`（[hsr/protocol/pb.py](../../hsr/protocol/pb.py)）。
   `Session._run` 用 contextvar 把 worker（及其子任务）绑到 `runtime.registry.pb`；
   `Registry(proto_dir)` 看到 `classes.desc` 就用 dynpb，否则回落到 4.6.54 生成模块。
   单测/离线 replay 不经过 session，仍拿旧模块，互不污染。
3. **字段名适配**：[proto/4.7.51/field_map.json](../../proto/4.7.51/field_map.json)。
   4.8 把不少字段改名并把编号搬走（`avatar_type`→`character_avatar_type`、
   `extra_lineup_type`→`lineup_type`、`slot`→`slot_id`、`world_id`→`curr_player_world_id`…）。
   加载快照时按表把 **4.8 的字段名改回 handler 用的名字**，字段号/类型一律不动——
   写出去的仍是 4.8 的线格式，handler 一行不用改。
4. **枚举**：枚举的*值编号*跨版本稳定、*值名*会变。`dynpb.EnumProxy` 允许用 4.6 的名字
   （`MissionStatus_MissionFinish`）取到 4.8 里的同一个号；消息别名表（`__messages__`）
   处理 `MazeGroup`→`MapInfoGroup` 这类改名。
5. **partial cmd 表**：`versions/4.7.51.toml` 加 `cmd_table = "partial"`；`Router.add` 对表里
   没有的命令只 warning 跳过（`router.skipped`），不再让服务端起不来。
   `scripts/check_proto.py` 把它当提示打印（`--verbose` 列全部）。

## 10. 补充新命令号的流程（2026-11-13 更新：已脚本化）

4.8 的 cmd id 与 4.6 没有任何算术关系，社区表（HyacineDH / FreeSR）也全不对，
只能拿客户端当 oracle。四个脚本串成一条流水线（细节见
[notes/2026-11-13-4.8协议攻坚与验收 §3](../notes/2026-11-13-4.8协议攻坚与验收.md)）：

1. **响应号**（客户端在线时）：
   `scripts/probe_cmd_ids.py --ids 700-799 --resume --out logs/probe_ids.json`
   给每个候选 id 发一帧 `0xff` 垃圾包体；客户端会打
   `Deserialize <消息名> meet exception` + `NullReferenceException at RPG.Client.XxxModule._OnCmdYyyScRsp`，
   未知 id 完全不产生日志。≈0.68 s/id，一个 100 号模块块约 70 s。
   **注意**：`Player.log` 每次启动清空；探测会刷 NRE，扫完要重启客户端。
2. **请求号**：`scripts/align_login_seq.py`
   拿一次已知版本的 `packets.log`（名字 + 包长）对齐当前版本（id + 包长），
   已知 id 当锚点、段长相等一对一、其余按包长模糊匹配 → `logs/cs_ids.json`。
3. **合并**：`scripts/merge_cmd_ids.py`
   要求 CsReq/ScRsp 同 100 块且双端齐全才写表；已有条目（ppSR 来源）不覆盖，
   冲突只报告 → `proto/4.7.51/CmdId.json`。
