## 1. 目标与非目标

### 目标

- **本地单人**：只监听 `127.0.0.1`；一个客户端；不需要账号体系/多会话/权限。
- **能进游戏、能跑图、能打凝滞虚影**：首版闭环。
- **可扩展**：新增一个功能 = 新增一个 handler + 一个 service + 可选资源表，不改网络层。
- **可验证**：每个功能都能用抓包回放/探针自动验证。
- **可调试**：包日志、proto dump、Lua 注入、客户端日志一条龙。
- **可换版本**：proto/cmd/资源/存档都带版本标记。

### 非目标

- 多人联机、公会、好友、聊天服务器。
- 服务端战斗模拟（客户端算）。
- 反作弊/安全加固。
- 完整复刻所有活动（用 dummy 先顶着）。
- 支持多个客户端版本（一次锁定 4.6.54）。

| 层 | 选择 | 理由 |
|---|---|---|
| 运行时 | Python 3.13/3.14（本机 3.14.6） | 本机已有；`asyncio` 成熟；`match`/类型语法好用 |
| 包管理 | `uv` + `pyproject.toml` | 本机已有 uv；锁文件可复现 |
| 并发 | 单事件循环 `asyncio` | 单人服无需多线程；KCP 定时器/心跳都在一个 loop |

## 4. 核心契约

### 4.1 Runtime

```python
# runtime.py
@dataclass
class Runtime:
    cfg: Config
    save: SaveManager
    res: Resources
    clock: Callable[[], int] = lambda: int(time.time() * 1000)

    @classmethod
    def load(cls, config_path: str) -> "Runtime": ...
```

- 单一实例，启动时构造，传给 UDP/HTTP 两边。
- **不要用模块级可变全局**（ppSR 的 `Manager` 类属性是反例）；测试时可以造多个 Runtime。

### 4.2 Handler 注册

```python
# game/router.py
Handler = Callable[[Session, Message], Awaitable[Message | None]]
HANDLERS: dict[int, Handler] = {}
REQ_TO_RSP: dict[int, int] = {}

def on(req_name: str):
    def deco(fn):
        rid = registry.id_of(req_name)
        HANDLERS[rid] = fn
        if rsp := registry.rsp_name_of(req_name):
            REQ_TO_RSP[rid] = registry.id_of(rsp)
        return fn
    return deco

async def dispatch(s: Session, cmd: int, body: bytes) -> None:
    fn = HANDLERS.get(cmd)
    if fn is None:
        await s.unknown(cmd)          # 可配置：silent / empty rsp / error
        return
    req = registry.decode_req(cmd, body)
    rsp = await fn(s, req)
    if rsp is not None:
        await s.send(rsp)
```

```python
# handlers/avatar.py
@on("GetAvatarDataCsReq")
async def get_avatar(s: Session, req: pb.GetAvatarDataCsReq) -> pb.GetAvatarDataScRsp:
    sync = roster.build_avatar_sync(s)
    return pb.GetAvatarDataScRsp(
        is_get_all=True,
        basic_type_id_list=[1001, 8001],
        avatar_list=sync.avatar_list,
        avatar_path_data_info_list=sync.avatar_path_data_info_list,
    )
```

约定：

- handler 名不必与 cmd 名一致，**显式传 cmd 名**，避免 echium 那种"下划线转驼峰 + 缩写"的坑。
- 返回 `None` = 不回包（用于通知类/可静默类）。
- 异常由 `dispatch` 捕获：记录 traceback，按策略回空包或断开；**绝不让一个 handler 崩掉整个服**。
- 需要发多个包时，用 `await s.send(...)` 多次，或返回 `list[Message]`。

### 4.3 Session

```python
class Session:
    conv: int
    addr: tuple[str, int]
    kcp: Kcp
    player: PlayerState          # 每个会话一个；单人服也保留，方便以后多开
    last_recv: float
    closed: bool

    async def send(self, msg, *, name: str | None = None) -> None: ...
    async def notify(self, msg) -> None: ...      # 同上，语义区分
    async def close(self) -> None: ...
```

- `send` 内部：`body = msg.SerializeToString()`；`cmd = registry.id_of(name or type(msg).__name__)`；`frame = encode(cmd, head=b"", body)`；`kcp.send(frame)`；`kcp.flush()`；`kcp.update(now_ms)`。
- 发送失败只记录，不抛出（客户端可能已断）。
- **不要**在 handler 里直接碰 socket/KCP；只通过 Session。

### 4.4 未知命令策略

```toml
[unknown]
mode = "empty_rsp"   # "silent" | "empty_rsp" | "error"
log = true
```

- `empty_rsp`：若 `CsReq` 能找到对应 `ScRsp`，回空 body；否则静默。
- `silent`：什么都不回（echium 对很多 cmd 就是这样，客户端能忍）。
- 建议默认 `empty_rsp`，并对 `SceneEntityMoveCsReq` 等高频包单独静默（避免日志爆炸）。

## 5. 网络层实现要点

### 5.1 UDP 入口

```python
class GameProtocol(asyncio.DatagramProtocol):
    def connection_made(self, transport): ...
    def datagram_received(self, data, addr):
        if len(data) == 20 and data[:4] == b"\x00\x00\x00\xff":
            self.on_connect(addr, data)
        else:
            s = self.sessions.get(addr)
            if s: s.feed(data)
```

- 会话 key 用 `(addr, conv)` 或只 `addr`；握手时记录。
- 单人服：`single_client=true` 时，新握手踢掉旧会话（或拒绝）。
- 每个会话一个 `asyncio.Task` 做 KCP update（`await asyncio.sleep(delay)`），或全局 10ms tick 遍历所有会话（更省）。
- `recv` 循环：一次 `input` 可能吐出多个应用消息，必须 while 取空。
- 半包：KCP 层保证消息边界；帧层仍要校验长度上限（如 8MB）。

### 5.2 KCP

- 直接移植 ppSR 的 `Kcp` 类；保留 `conv_mode` 抽象：

```python
class KcpCodec(Protocol):
    def encode_seg(self, conv: int, ...) -> bytes: ...
    def decode_seg(self, buf: bytes) -> Seg: ...

class ConvTokenLE(KcpCodec): ...   # echium 风格：conv u32 LE + token u32 LE
class ConvU64BE(KcpCodec): ...     # ppSR 风格：conv u64 BE
```

- 自测：同一段 `(conv, token, cmd, payload)` 两种编码分别 round-trip；再用抓包判定真实客户端用哪种。
- 参数：MTU 1400、nodelay(1,10,2,1)、wnd 256/256（比 echium 更抗丢包）。
- 时间：`int(time.monotonic()*1000) & 0xFFFFFFFF`，避免系统时间回拨。

### 5.3 帧与 head

- 解析：`cmd, head_len, body_len = struct.unpack_from(">HHI", buf, 4)`。
- head 只记录不解释；回包 head 恒空。
- 客户端 head 序号可用于检测丢包/乱序（调试日志），但不要据此拒绝。

### 5.4 心跳

- 15 秒无任何包 → 关闭会话（客户端 5s 一次）。
- 响应 `client_time_ms` 原样回填；`server_time_ms` 用真实时间。
- 心跳里可选挂 Lua 脚本（`ClientDownloadData`），由 `features.lua_console` 控制。

- `scripts/gen_proto.py`：

```bash
       --descriptor_set_out=proto/hsr.desc --include_imports proto/StarRail.proto
```

```python

def message_cls(name: str) -> type[Message]: ...   # 去尾部数字回退
```

### 7.2 原子写

```python
def save_atomic(path: Path, data: str) -> None:
    tmp = path.with_suffix(path.suffix + ".tmp")
    tmp.write_text(data, encoding="utf-8")
    os.replace(tmp, path)
```

## 11. 质量门槛

- 单包处理 p99 < 10ms（本机）。
- 启动 < 1s（不含资源表加载）；资源加载 < 2s。
- 内存 < 200MB（不含 66GB 资源，资源不加载）。
- 0 未捕获异常导致进程退出；handler 异常率可见。
- `pytest` 覆盖：frame/kcp/registry/save 单测；登录流程集成测试；抓包回放回归。
- 每加一个 handler，至少加一个 probe 用例。

## 12. 从三套实现里抄什么、不抄什么

| 来源 | 抄 | 不抄 |
|---|---|---|
| echium | handler 装饰器 + dummy 策略；多命途折叠；战斗 buff 规则；Lua 注入；同步顺序 | TCP shim；FakeConnection 在 import 时执行 handler；全局可变状态；密码门 |
| pearl | 数据驱动场景/关卡；挑战状态机；抽卡保底；资源表解析；秘技规则表 | TCP + 客户端补丁；每连接一线程；C 风格内存管理（我们用 GC） |
| ppSR | 纯 Python KCP；握手；最小闭环；services/handlers 分层；freesr 模型 | 单 socket 类属性；密码门；阻塞收包线程；全局 Manager |

## 13. 风险与对策

| 风险 | 对策 |
|---|---|
| KCP 头编码不确定 | 双编码器 + 抓包实测（Phase 0 第一件事） |
| proto 字段漂移 | 锁 build；抓包回归；未知字段保留 |
| 资源表缺失 | 先用 pearl 资源；DesignData 抽取作为独立任务 |
| 客户端闪退定位难 | Player.log + 最后 N 帧日志 + 二分注释 handler |
| 存档损坏 | 原子写 + bak + schema 迁移 |
| 端口冲突 | 配置化；启动前检测；明确提示 |
| 反作弊/保护 | 不注入内核；静态分析优先；本地代理正常登录 |
| 范围膨胀 | 按 Phase 验收；活动一律先 dummy |
