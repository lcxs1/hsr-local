## 1. 一句话

`hsr-local` 是一个**纯 Python 写的本地单人《崩坏：星穹铁道》服务端模拟器**：UDP + KCP 直连，
不用 TCP shim、不改客户端、没有密码门。目标客户端三个 profile ——
4.7.51（`OSBETAWin4.7.51`，实际是 4.8 beta，build `17100438`）、
4.7.0 CN（`CNPRODWin4.7.0`，build `17108910`）、
4.6.54（`OSBETAWin4.6.54`，build `16927089`）。

截至归档：**能登录、进筑梦边境 20313、跑图 / 换队 / 切命途 / 换皮肤、打凝滞虚影并连续再战、
混沌回忆（MOC）完整 15 层闭环**；4.8 beta 客户端上登录 / 跑图 / 换队 / 换皮肤 / 进战斗 / 结算
全部真机通过。**没到「能玩」的程度**，是一个把协议、数据、战斗流程都跑通的学习型工程。

规模（归档时，数字口径见 [docs/README §3](../README.md#3-关键数字唯一事实源)）：
**262 单测 / 88 个 handler（4.7.51 上只注册了 31 个，另 57 个缺命令号）/
4.7.51 命令表 140 条 / 服务端 1.1 万行 Python / 仓库约 12 MB（含数据与协议快照）**。

## 2. 为什么停在这里

2026-11-14 作者决定停止开发并归档。客观上的三个坎（都有对应记录，不是"感觉做不完"）：

1. **4.8 命令号缺口**：4.7.51 是 4.8 beta，命令号与字段号相对 4.6.54 整体重排，
   社区现成的表（HyacineDH / FreeSR）一条都对不上，只能拿客户端当 oracle 人工反查
   （给客户端发非法包体，从 `Deserialize <msg> meet exception` 反推，≈0.68 s/条）。
   到这轮结束已经从 79 条补到 140 条，**还剩 57 个 handler 没有命令号**；
   补完还要按同样方式补响应号、再做真机验收。这是纯人力活。
2. **混沌回忆下半黑屏**：换半场已按正式服抓包逐字段复刻并真机通过（客户端会对下半的怪出手），
   但**第二场战斗本身进不去**——客户端黑屏约 9 s 后自行判胜（`turns=0`）。
   7 轮真机已经排掉 9 类原因，包层面已无差异可对；再往下要用 Process Monitor 看那 9 秒
   客户端在等什么，投入产出不划算。详见
   [notes/2026-11-12-下半黑屏收工快照](../notes/2026-11-12-下半黑屏收工快照.md)。
3. **版本升级是重复劳动**：客户端每个大版本都要重做描述符快照、字段改名映射、命令号反查、
   数据表导出与整轮真机回归（见 [reference/02](../reference/02-开发与版本更新.md) 的升级 SOP）。
   单人维护跟不上官方发版节奏。

结论：作为学习项目它已经到点——协议层、数据层、战斗结算链路都验证过了，
**剩下的不是"想不明白"，而是"不想再花时间"**。于是冻结、归档。

## 5. 怎么把它跑起来（最小复现）

需要自备：**Python 3.13+**、**Windows**、**自己合法拥有的游戏客户端**（4.6.54 / 4.7.0 / 4.7.51 任一）、
**一个能把登录域名转到 `127.0.0.1:21000` 的 HTTPS 代理**（本项目用 `firefly-go-proxy`，
游戏客户端与代理都**不在仓库内**，仓库也不分发任何游戏资源）。

```powershell
git clone https://github.com/lcxs1/hsr-local.git
cd hsr-local

py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -U pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# 起服务端（默认 profile 4.7.51，UDP 23301 / SDK 21000）
.\run.ps1
# 或：.\.venv\Scripts\python.exe -m hsr
# 严格模式（数据 id 有问题直接退出）：python -m hsr --strict
# 换 profile：python -m hsr --profile 4.6.54
```

正常应看到：

```text
  hsr-local · OSBETAWin4.7.51 · profile=4.7.51 · uid=10001
  game   udp://127.0.0.1:23301
  sdk    http://127.0.0.1:21000
```

然后另开窗口起代理并启动游戏（把 `$Client` 换成自己的客户端目录）：

```powershell
$Client = 'X:\HSRSiFu'
Start-Process "$Client\firefly-go-proxy.exe" -ArgumentList `
  '-e', "$Client\StarRail_4.7.51\StarRail.exe", '-p', '9978' -Verb RunAs
```

代理要把登录域名指到 `127.0.0.1:21000`，系统代理指向 `127.0.0.1:9978`。
停在 HoYoPass 登录窗不连接，通常是代理没拦住 HTTPS。详细配置表见
[guide/01-运行与配置](../guide/01-运行与配置.md)。

> 仓库里的 `config.toml` 默认 `[features].local_cdn = false`（这样开箱就能跑 `check.ps1`）。
> 真机跑 **4.7.0 CN / 4.7.51** 时要改成 `true`，并把 `[paths].client_dir` 指向客户端安装目录
> （`StarRail_Data` 的上级）；4.6.54 走真实 CDN，不用改。

**不开客户端也能验证**（归档后仍可复现的离线部分）：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests   # 262 单测
.\.venv\Scripts\python.exe scripts\replay_flows.py         # 离线 5 条链路回放
.\.venv\Scripts\python.exe scripts\bot_smoke.py            # 无客户端 e2e：真 UDP/KCP 登录→战斗
.\.venv\Scripts\python.exe scripts\bot_smoke.py --profile 4.6.54 --challenge --peak
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\check.ps1   # 以上全量 + ruff + 文档检查
```

`check.ps1` 会起一次性服务端跑 bot e2e，端口随机、用 `.tmp/` 存档，不碰 `saves/`。

## 6. 仓库结构

```text
hsr/                服务端代码（net/dispatch/game/protocol/tools）
  net/              UDP / KCP / 握手 / 帧 / 会话
  dispatch/         HTTP 登录链 / hotfix / 本地 CDN / 网关线格式
  game/             88 个 handler + services（角色、场景、战斗、挑战、终局）
  protocol/         proto 注册、编解码、4.8 动态描述符（dynpb）
proto/              StarRail.proto、CmdId.json、hsr.desc（4.6.54 基线）
proto/4.7.51/       4.8 beta 描述符快照 + 命令表 + 字段改名映射
data/               静态数据（freesr / endgame / stages / tutorials / progress）
versions/           三个客户端 profile（4.6.54 / 4.7.0 / 4.7.51）
tests/              32 个测试文件 / 262 条
scripts/            回归、真机测试、数据导出、命令号反查
docs/               指南 / 设计 / 参考 / 笔记（入口 [docs/README](../README.md)）
lua/                Lua 控制台脚本
saves/             运行时存档（不入库）
logs/              运行时日志与真机报告（不入库）
```

关键文件：

| 文件 | 作用 |
|---|---|
| `hsr/config.py` | 配置模型与默认值（`config.toml` 的全表见 guide/01） |
| `hsr/version.py` / `versions/*.toml` | 客户端版本 profile |
| `hsr/net/` | 20 B 握手、KCP、帧、会话 |
| `hsr/protocol/dynpb.py` | 从 4.8 描述符运行时建类（4.7.51 的关键） |
| `hsr/game/services/challenge.py` | 混沌回忆 / 终局挑战状态机 |
| `hsr/game/handlers/battle.py` | 战斗开始 / 结算 |
| `proto/4.7.51/field_map.json` | 4.8 字段改名表（只改名不动号） |

## 11. 关于本仓库里的本机路径

文档和脚本里残留不少 `E:\LCXS\...`、`E:\SiFu\...` 这样的路径，那是**作者当时那台机器**的
目录布局（参考工程、抓包工具、客户端、`tools/official/`），在你的机器上大概率不存在。
它们只作"当时东西放在哪"的线索，不代表仓库内容；需要复现时按自己的布局替换即可。
`config.toml` 的 `[paths].client_dir` 默认留空，就是为了不在仓库里写死机器路径。
