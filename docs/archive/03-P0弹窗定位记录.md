> ## ✅ 2026-11-08 最终结论（先看这个）
>
> 弹窗的**真正根因**是 `GetTutorialGuideScRsp` 里指南组的 `type` 字段：
> 客户端 `UnlockTutorialGuideCsReq` 对组级指南发 `type=0`
> （`TutorialGuideDefault`），服务端必须回 **GroupID + `type=0`**。之前先错在
> 返回单条 guide id（110101），后来错在按 `TutorialType` 把 57 组标成 `type=1`；
> 客户端因此认为它们没完成，每次登录重发 57 条解锁请求，按顺序弹
> 「位面规则」/「欢愉命途」/「G 多层韧性」。
>
> 修复：`scripts/export_tutorials.py` 全部输出 `type: 0`，
> `data/tutorials.json` 864 组全为 0，`hsr/game/handlers/mission.py` 的 extra
> 也用 0。**真机复测：`UnlockTutorialGuideCsReq` 57 → 0，弹窗和 G 提示都消失。**
>

> 根因推翻；日常验证请直接用 [测试与回归](../guide/02-测试与回归.md) +

## 0. 为什么需要你来测

客户端以**管理员**权限运行，DSH 进程是普通权限，Windows 的 UIPI 会拦掉注入的
鼠标事件，所以自动化点不了任何按钮。但**弹窗本身不需要点击**：登录后它自己出现。
因此只要有人把游戏启动起来，剩下的（等待、截屏、收日志、出报告）都可以自动完成。

你只需要：

1. 关掉上一次的游戏/服务端；
2. 跑一条命令；
3. UAC 弹窗点「是」；
4. 等脚本自己截完 3 张图（约 90 秒，**期间不要碰鼠标键盘**）；
5. 回车结束，把报告和截图发回来。

## 1. 前置检查（30 秒）

- 游戏 `StarRail.exe` 已完全退出（任务管理器里没有）。
- 上一轮的服务端已关闭（没有窗口在跑 `python -m hsr`）。
- 系统代理可以正常被 firefly 设置；测试结束脚本会把 `ProxyEnable` 置 0。

## 2. 推荐：一条命令跑一轮

在 `E:\LCXS\hsr-local` 打开 **Windows PowerShell**（不需要管理员），执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\exp_popup.ps1 -Experiment baseline
```

脚本会依次做：

| 步骤 | 说明 |
|---|---|
| 1 | 生成临时配置 `logs\exp\all-<时间>.toml`（只启用实验开关，不改 `config.toml`） |
| 2 | 后台启动服务端（UDP 23301 / HTTP 21000） |
| 3 | 启动 `firefly-go-proxy.exe` 并以管理员权限拉起游戏（**UAC 点「是」**） |
| 4 | 等 `PlayerLoginFinishCsReq`（= 客户端登录完成） |
| 5 | 登录后 10 / 25 / 40 秒各截一张全屏图 |
| 6 | 汇总 `logs\packets.log`、`Player.log`，写 `logs\exp\all-<时间>.report.md` |
| 7 | 你按 Enter 后：停服务端、停代理、`ProxyEnable=0` |

**测试期间不要点「关闭」，也不要移动鼠标**（脚本要抓弹窗还在的画面）。

### 顺手验证 Phase 2 战斗（可选，但建议做）

三张截图拍完后，脚本会停住并提示「完成游戏内操作后按 Enter」。这时你可以：

1. 如果「位面规则」还在，点「关闭」；
2. 走到凝滞虚影（大世界里的黄圈），按 **F**；
3. 选关卡 → 开始战斗 → 打到结算；
4. 再打一次，确认能重复；
5. 回到 PowerShell 窗口按 **Enter**。

脚本会在你按 Enter 之后才收集日志，所以战斗请求也会进报告。战斗不要求
人工判断「对不对」，有异常直接看报告里的「战斗（Phase 2）」段和
`Player.log` 异常；我会根据 `start cocoon: cocoon_id=… -> stage=…` 这条
日志把客户端的 cocoon id 映射补上。

### 成功时你应该看到

```
[exp] 服务端已就绪 (PID xxxxx)
[exp] 启动 firefly 代理 + 游戏（UAC 弹窗请点“是”）
[exp] 等待客户端登录（最多 240 秒）…
[exp] 检测到登录完成。接下来会自动截 3 张图…
[exp] 截图：…-1.png …-2.png …-3.png
报告：E:\LCXS\hsr-local\logs\exp\all-<时间>.report.md
```

### 需要发回来的东西

1. `logs\exp\all-<时间>.report.md` 的内容（或整份文件）；
2. 三张截图（`all-<时间>-1.png` / `-2.png` / `-3.png`）；
3. 如果你看到弹窗，顺手描述一下标题（例如「无尽膨胀奇物」还是「无尽膨胀碎片」）；
4. 如果打了一场战斗，报告里的「战斗（Phase 2）」段会自动带上
   `StartCocoonStageCsReq` / `PVEBattleResultCsReq` 和 `start cocoon:` 日志。

> 截图和报告都在 `E:\LCXS\hsr-local\logs\exp\`，按时间排序就是最新一轮。

## 4. 实验开关与预设

`config.toml` 的 `[experiments]`（默认全关）由脚本临时覆盖，**不要手改主配置**。
预设越靠后覆盖越多：

| 预设 | 含义 |
|---|---|
| `baseline` | 登录态开关全关，SDK `getConfig` 用 `announce_url=""` + `enable_announce_pic_popup=false`（**下一轮用**） |
| `sdk404` | 登录态开关全关，SDK `getConfig` 直接返回 404（pearl-sr 的做法；`baseline` 无效时用） |
| `mission` | `GetMissionData` / `GetMissionStatus` 返回全部主线已完成 |
| `quest` | `GetQuestData` 返回全部任务已完成 |
| `activity` | `GetActivityScheduleConfig` 返回 347 条活动模块，时间窗**已结束** |
| `activity_active` | 同上，但时间窗为**进行中** |
| `basicinfo_omit` | `GetBasicInfoScRsp` **不发送** `player_setting_info` |
| `basicinfo_nested` | 发送并补齐 `player_setting_info` 的三个嵌套子消息 |
| `core` | mission + quest + activity(ended) |
| `all` | core + basicinfo_nested（已实测无效，留作对照） |

第一轮用 `baseline`（登录态开关全关）：此时唯一的变量就是 SDK `getConfig` 的
公告弹窗修复。如果弹窗消失，说明根因就是它；如果还在，再回头做下面这些开关的二分。

## 4.5 小红点 / 跳出的教程提示（已解决，历史）

客户端的指南/教程本地状态在注册表：

```
HKCU\Software\Cognosphere\Star Rail
  User_<uid>_UnlockedTutorialGuides   (JSON 数组 + 结尾 NUL)
  User_<uid>_FinishedTutorials        (JSON 数组 + 结尾 NUL)
```

**实测：客户端每次登录会重写这两个值**（`FinishedTutorials` 清空，
`UnlockedTutorialGuides` 变回它自己的约 1804 条），所以 `fix_client_prefs.ps1`
不能作为长期方案。真正修复是 `type=0`（见文首）；修复后
`UnlockTutorialGuideCsReq = 0`，「G 多层韧性」提示和「欢愉命途」弹窗都消失。
剩下的红点是本地历史缓存，可忽略。

`scripts/fix_client_prefs.ps1` 仍保留，仅用于 `game_test.ps1 -PatchPrefs` 对照实验。

## 5. 常见问题

| 现象 | 处理 |
|---|---|
| `HTTP 21000 已被占用` | 上一轮服务端没关。`Get-NetTCPConnection -LocalPort 21000 -State Listen` 找到 PID 后 `Stop-Process -Id <pid> -Force`。 |
| `UDP 23301 已被占用` | 同上，`Get-NetUDPEndpoint -LocalPort 23301`。 |
| `检测到 StarRail.exe 还在运行` | 完全退出游戏再跑。 |
| 一直停在「等待客户端登录」 | 代理没把登录域名指到 `127.0.0.1:21000`；看 `logs\packets.log` 里有没有 HTTP 请求；系统代理是否 `ProxyEnable=1`。 |
| 卡在 HoYoPass 登录窗 | 代理没有拦截 HTTPS，确认 `ProxyEnable=1` 且指向 `127.0.0.1:9978`。 |
| 截图全黑 | 游戏用独占全屏；改成「无边框窗口」再跑。 |
| 报告里 `Player.log 最后写入` 早于测试时间 | 客户端本次没写日志，异常栏不可信，以截图为准。 |
| 弹窗还在，想手动清 SDK 公告缓存 | 先 `Get-ItemProperty 'HKCU:\Software\Cognosphere\Star Rail' \| Select-Object *MIHOYOSDK_ANNOUNCE_URL*` 确认，再 `Remove-ItemProperty 'HKCU:\Software\Cognosphere\Star Rail' -Name 'MIHOYOSDK_ANNOUNCE_URL_h25198164'`（测试器已自动做）。 |

## 6. 判定标准

- **三张截图里任何一张看不到「位面规则」面板** → 该组合有效；
- **三张都还弹着** → 该组合无效；`baseline` 无效就跑 `sdk404`；两者都无效，
  说明弹窗内容是本地的，下一步做「清 webview 缓存 / 拦截公告域名」诊断。
- 只需要「弹/不弹」这一个二值结果，不需要你点弹窗、不需要进世界。

## 7. 跑完之后

把报告 + 截图发回来。我会：

1. 读取截图确认弹窗状态（不依赖你的描述）；
2. 根据 `packets.log` 的请求序列和 `Player.log` 的异常决定下一组实验；
3. 一旦确定有效组合，把它写回 `config.toml` 的默认值，并更新
   [交接与排障](../guide/03-交接与排障.md) 与 README。

> 如果 `all` 一轮就压掉了弹窗，就只剩一件事：用二分确定最小组合（通常再跑
> 1~3 轮，每轮约 2 分钟），然后把结论固化。
