## 2. 四个真问题与修法

### 2.1 进游戏卡 13 秒（两个叠加原因）

1. hotfix 报的 `ifix_version=17102685` 在本地 CDN 没有对应包，客户端每次 `M_IFixV.bytes`
   都 404，再按 3 s/9 s 退避重试——这就是那十几秒的大头。
   修法：`data/hotfix.json` 的 `OSBETAWin4.7.51` 条目把 `ifix_version` 置 `"0"`、
   `ifix_url` 指向 `output_0_…`（和 4.6.54 一致），客户端不再请求 ifix。
2. `GetBasicInfoScRsp` 的 `PlayerSettingInfo` 在 4.8 换了子消息结构，空/缺字段会让
   `RPG.Client.PlayerModule._CmdGetBasicInfoScRsp` 抛 `NullReferenceException`。
   修法：`handlers/login.py` 的 nested 模式改成**按 schema 遍历**，给所有 message 类型
   子字段填一个空实例（`field.type != 11 or is_repeated` 跳过），新版本加字段也不用改代码。

### 2.2 无法切换队伍：`slot` 改名换号

| 4.6 | 4.8 | 影响 |
|---|---|---|
| `LineupSlotData.slot`（9） | `slot_id`（13） | `ReplaceLineupCsReq` 里 `slot_data.slot` → `AttributeError: slot` |
| `JoinLineupCsReq.slot`（1） | `slot_id`（15） | 直接邀请入队同样炸 |

处理进 `proto/4.7.51/field_map.json`（**只改名，不动字段号**），handler 侧零改动。

### 2.3 结算显示"战斗失败"：`check_identical` 改名换号

`PVEBattleResultScRsp.check_identical` 在 4.8 = 字段 11 `DLMDAIOKKEO`(bool)。旧 handler 写
`rsp.check_identical = True` 直接 `AttributeError` → 整个结算包发不出去 → 客户端按失败处理。
这条特别隐蔽：**战斗本身能打、伤害正常**，只有收尾包挂了。

### 2.4 新解锁 handler 又暴露 4 处改名

| 消息 | 4.6 字段 | 4.8 字段 |
|---|---|---|
| `Challenge` | `star` / `score_two` | `stars` / `score_second` |
| `ChallengeGroup` | `taken_stars_count_reward` | `taken_challenge_reward` |
| `GetPlayerBoardDataScRsp` | `current_head_icon_id` | `head_icon_id` |
| `GetLineupAvatarDataScRsp` | `avatar_data_list` | `lineup_data_list` |

这些是"把 handler 从 skipped 状态解锁之后"才暴露的——**解锁一批 handler 就要重跑一次
填充式演练**，否则下一个炸点只是等着真机触发。

## 3. 方法：4.8 命令号怎么反查出来的（79 → 140）

4.8 的 cmd id 与 4.6 **完全不共享**（不是加减偏移，社区表也全对不上），只能用客户端自己当 oracle。

### 3.1 响应号：非法包体 oracle（`scripts/probe_cmd_ids.py`）

给客户端发一帧"id 候选 + `0xff` 垃圾包体"：

```
[Network] Deserialize PPNMNDKILGL meet exception Google.Protobuf.InvalidProtocolBufferException
System.NullReferenceException
  at RPG.Client.BattleModule._OnPvebattleResultScRsp (System.UInt16, System.Object)
```

* 第一行给出 4.8 快照里的**消息名**（`PPNMNDKILGL`，可用 `classes.desc` 反查字段结构）；
* 栈里 `_OnXxxScRsp` 给出**语义名**（`PvebattleResultScRsp`）；
* 未知 id 完全不产生日志 —— 判别力天然干净。

实测每 id ≈ 0.68 s（`urllib` + 0.25 s 读日志 + 0.4 s 间隔），一个 100 号的模块块 ≈ 70 s。
注意客户端 `Player.log` 每次启动会**清空**，所以扫之前不要重启客户端。

### 3.2 请求号：登录序列对齐（`scripts/align_login_seq.py`）

同一个客户端版本每次登录发的请求**顺序固定**，所以拿 4.6 的 `packets.log`（有名字 + 包长）
去对齐 4.8 的 `packets.log`（只有 id + 包长）：已知 id 当锚点，锚点之间长度相等的段一对一，
长度不等再用包长做 `difflib` 模糊匹配。137 条里 119 条是"段长完全相等"的高置信配对。

### 3.3 合并（`scripts/merge_cmd_ids.py`）

请求号与响应号**必须同模块同 100 块**（4.6/4.8 都成立，例：`GetBagCsReq 583 / ScRsp 554`、
`GetCurSceneInfoCsReq 1407 / ScRsp 1491`），两条都拿到才写表；已有条目（ppSR 来源）一律不覆盖，
冲突只报告。本轮结果：`GetPlayerBoardData 2883/2854`、`GetMissionData 1283/1254`、
`GetMarkItemList 559/582`、`GetQuestData 983/954`、`GetLineupAvatarDataScRsp 743`、
`SwitchLineupIndexScRsp 788`、`InteractPropScRsp 1442`、`GetUnlockTeleportScRsp 1466` 等。

### 3.4 填充式演练（`scripts/exercise_handlers.py`）

对每个已注册 handler 构造"所有标量=1、所有 message 递归填一层"的请求再执行，
专门抓"空请求跑得通、真包才炸"的字段改名。这就是本轮抓出 2.4 那 4 处的工具，
现在 31/31 通过。

## 4. 教训

1. **新客户端第一件事是验"重排"，不是补 handler。** cmd id 与字段号可能整体重排；
   先比 `PlayerGetTokenCsReq` 首包 id 与几个高频消息的字段号，再决定工作方式。
2. **字段看号不看名。** 4.8 大量 `slot→slot_id`、`star→stars` 这类换名换号；只按名字找会
   找到"看起来对"的错字段。改名字段优先写 `field_map.json`，handler 不动。
3. **空请求演练会漏 bug。** `exercise_handlers.py` 之前所有 handler "通过"是因为请求全空，
   根本走不到 `slot_data.slot`、`check_identical` 这些分支。演练必须填满字段。
4. **"没有报错"不等于正常。** router 会把 handler 异常吞成一行 `handler ... failed`，
   对客户端表现是"卡住 / 判失败"。验收先数 `handler .* failed`，再看画面。
5. **空回包会打出 NRE。** 客户端对缺失的 message 子字段（`PlayerSettingInfo`、`ArchiveData`）
   会 NRE；宁可给空实例，也不要省略。
6. **客户端日志是唯一权威 oracle。** `Deserialize <type> meet exception` + `_OnXxxScRsp` 栈名
   能把 id↔消息名直接反查出来；社区表（HyacineDH / FreeSR）在 4.8 上全是错的，不要用。
7. **命令号有结构可借力。** req/rsp 同 100 块、模块块跨版本基本保留、登录顺序固定 ——
   这三条让"没有全量表"也能把表补到够用。
8. **探测是有代价的。** 每个探测都会让客户端抛一次 NRE、污染 UI 状态；扫完必须重启客户端，
   扫的时候不要让用户玩。
9. **进程权限会挡住自动化。** firefly 代理用 `-Verb RunAs` 起 → 游戏提权 → 普通权限 shell
   `Stop-Process` / `taskkill` 全部 `Access is denied`（对照：`notepad` 可以杀）。要让 agent
   能自己重启客户端，代理必须普通权限启动。
10. **数字只写一处。** handler/单测/命令表条数只在 [docs/README §3](../README.md#3-关键数字唯一事实源)
    维护，其余文档引用它，避免"文档说 79、实际 31"这种漂移。
