# 规则修订：v1 为什么拖慢开发（2026-11-11）

> **状态**：笔记（不是事实源；结论已回填 [AGENTS.md v3](../../AGENTS.md)）　**适用版本**：4.6.54（build 16927089）/ 4.7.0（build 17108910）　**最后修订**：2026-11-11

## 0. 结论

v1 把“安全”和“速度”混成一件事：默认最严、按文件数判定、完成权收在人手里。
结果是**审批从例外变成常态，人成了单线程瓶颈**，而真实风险并没有因此降低多少。

v2 改成：默认放行 → 按回滚成本分级 → 证据分级 → 只有不可逆/外溢的事才等批准。
v3 再松一档：**只留「不伪造验证」一条硬约束，其余全部降级为建议**——因为 v2 的分级表本身还是审查工作。

## 2. 七条阻碍

### 2.1 用“文件数”判大改 → 所有真实工作都变成大改

v1 §2.2 写“改 3 个及以上文件”就是大改，必须先给计划、等确认。
而一个正常功能最少动 handler + service + data + test ≥4 个文件，于是**审批成为默认路径**。
v1 §2.2.1 自己也承认“逐条报批会逼着 Agent 攒几百行大 diff 再交，审的人更容易漏”。
**→ v2 取消文件数判据；v3 直接取消审批本身。**

### 2.2 “客户端可见”定义过宽 → 几乎全部改动都要真机 + 人确认

v1 §2.3 把“下发给客户端的字段值 / Notify 顺序”都算可见行为。
私服的每一行改动几乎都会改变下发内容，于是**每个改动都压到真机上**；
而真机依赖：人在、游戏能开、UAC、客户端 30–45 s 启动、一次一个会话。
文档里已经出现“**要动存档结构（`saves/player.json`），按 AGENTS §2.2 需人批准，批准前不动**”
（`design/03` §6）——PF/AS 解锁卡在这里，而它属于 P0/P1 范围。
**→ v2 拆成 V0–V3；v3 直接说：真机不是完成条件。**

### 2.3 完成定义只有“人确认”一条路 → 主线无法闭环

v1 §4：客户端可见行为“不可以自行宣布”完成。叠加上面的宽口径，Agent 永远只能说“待真机”。
人不在 → 工作停摆；代码写完也不能宣布结果。
**→ v2 分“合入 / 可上线 / 对外宣称”；v3 只剩一条：有证据就算完成。**

### 2.4 回放门槛与“挑战链回放未补齐”互相卡死

v1 §2.3.1：回放能覆盖的必须先写回放，且“拿回放跑不出来当跳过真机的理由”被禁止。
但 `hsr/replay.py` 只覆盖核心 5 链路（`run_core_flow`），挑战链至今没有回放用例。
于是挑战类改动既不能先上真机，也没有回放可用，只能停在“待真机”。
**→ v2 取消阻塞；v3 更进一步：回放是工具，不是闸门。**

### 2.5 文档税：写代码 10 分钟，对账 30 分钟

v1 §7 要求 6 个位置同步、每篇头部日期、数字只改一处、不写历史过程。
实际“193”仍散落 10 处、“74 handler” 4 处，编号与元信息靠人肉维护，
`AGENTS.md` 自己膨胀到 476 行、内嵌大量技术细节，和 `docs/` 形成双份事实源。
**→ v2 只留契约同步；v3 只强制 `CHANGELOG.md` 一行。**

### 2.6 没有 git，回滚靠手搓备份

7 个 `E:\LCXS\backup` 目录，回滚 = 复制回去，不可验证、不可差分、不可 bisect。
这反过来又支撑了“大改必须审批”的心态（因为回滚不可靠）。
**→ 已 `git init`（基线 `86745c9`），回滚 = `git revert`。**

### 2.7 数据/联网授权颗粒度过细 → 卡住最大短板

社区笔记 §3.1 已经指出：数据缺口（缺 `ChallengeGroup`、轮换表、通关历史）比代码质量更关键。
但 v1 §10 要求“每个目标版本单独授权”，§2.4 要求“只读资料检索逐次申请”。
4.7 新皮肤 id 就卡在“需要 4.7 的 `AvatarSkin` 表”上。
**→ v2/v3 改为常规做法：公开配置表 + hotfix 元数据，记来源与 SHA256 即可，不问。**

## 3. 保留什么（v1 里真正值钱的部分）

- `scripts/check.ps1`（单测 + 回放 + proto + ruff + 文档检查）——七个参考工程都没有等价物；
- `hsr/replay.py` + `tools/golden` 冻结基线——社区没有协议级回归；
- 一条底线：**不伪造验证**。

v3 没有削弱这些，只是把“每次都要人签字”换成“每次都要机器或日志证明”。

## 4. 决策（2026-11-11 已拍板）

1. **玩法口径**：默认 A（模拟器口径）。B 未通前 A 必须可用；新玩法先按 A 交付。见 AGENTS §5。
2. **git**：已初始化，基线 `86745c9`；回滚 = `git revert`。
3. **数据**：公开配置表 + hotfix 元数据属常规做法，记 URL / SHA256 / build 即可，见 AGENTS §6。
