## 1. 为什么不用网卡嗅探

1. 本机没有 Npcap，装驱动要管理员 + 可能重启；
2. 更关键：**官方 UDP 载荷是加密的**，嗅探下来也是乱码；
3. 中继方案不要驱动、不要管理员，抓到的还是**解密后**的帧。

## 2. 三条链路（与私服同构，只是终点换成官方）

```text
StarRail.exe --(系统代理 :9978)--> firefly-go-proxy
     firefly 用自带 CA 终止 TLS，把登录域名反代到 127.0.0.1:21000（保留 Host 头）
       --> mirror.py :21000
             逐字节转发到 https://<Host><path>（官方 dispatch / SDK 原样请求原样返回）
             唯一改写：/query_gateway 的 GateServer.ip/port -> 127.0.0.1:23301
             顺手落盘 client_secret_key（EC2B）
StarRail.exe --(UDP :23301)--> relay.py --(UDP)--> 官方游戏服
             透明中继；实时解密并写 capture.bin
```

差别只在两点：私服自己造登录响应，这里**透传官方**；私服明文，这里**要先解密**。

## 3. 加密（这是抓包工作的主体）

依据 DanhengServer `Common/Util/Security/{Ec2b,MT19937,Crypto}.cs`，并用 .NET 10 编译原实现
逐值交叉验证（`tools/official/_csvec/`）。

| 阶段 | XOR 密钥 | 来源 |
|---|---|---|
| 连接开始 → `PlayerGetTokenScRsp`（cmd 71） | EC2B 静态密钥 4096B | `query_gateway` 的 `GateServer.client_secret_key`（field 403 = base64 的 2076B EC2B） |
| 之后全部 | MT19937(`secret_key_seed`) 4096B | cmd 71 body 的 field 11（u64） |

- XOR 是 4096 字节循环掩码，**整帧**（含 `9D74C714` 魔数）参与，每帧从 key[0] 重来；
- 两把钥匙的 u64 字节序不同：EC2B 小端、seed 大端（原实现如此，别「修」）；
- relay 每帧先试明文再试两把钥匙，假设错只会退化成「未解密」，不会静默写坏。

## 7. 已知坑

- **维护期抓不到**：`query_gateway` 回 `retcode=3 / "client version not match"` 时没有 ip/port，
  mirror 会打 `gateway NOT rewritten: no ip/port in GateServer`——这就是「等开服」的信号；
- **签名**：不带客户端自己的签名参数直接 GET `query_dispatch` 会回 `{"retcode":3}`，
  所以 mirror 只透传、不自己拼参数；
- **firefly 要 UAC**：跑完确认系统代理已恢复（否则浏览器/其他程序会指到 9978）；
- 源 IP 仍是本机公网出口，与直连一致，不是代理 IP。

## 9. 与 hsr-local 现有实现的差异（可直接改）

1. **不要重建场景**：换半场里官方**没有** `SyncServerSceneChangeNotify` / `EnterSceneByServerScNotify`，
   全程原地换实体组。现在的 `advance=sync`（整份新 `SceneInfo`）方向就是错的。
2. **上半的怪要先删**（group 9，type=3，delete_entity），不是"不卸载旧组"。
3. **角色实体要一起换**：官方显式删掉上半 4 个角色实体、加入下半 4 个角色实体（`add_entity` +
   `actor.base_avatar_id` + `motion`）。hsr-local 只发 `SyncLineupNotify`，场上实体没换。
4. **`ChallengeLineupNotify` 之后才声明新组**：group 10 用 `group_info` 整组 + `LOADED`，
   顺序是"删旧怪 → 换角色实体 → 换阵容 → ChallengeLineupNotify → 声明新组 → 移动通知"。
5. **`PVEBattleResultScRsp` 最后发**（在全部换半场包之后 1–80 ms），不是先 ack 再推。
6. **`refresh_type=3` 是"删/改实体"**，不是 1/2。`guide/03` 坑 35 里"LOADED 在 4.7.0 是激活组"的解释要按这条修正。
7. 官方发了 **4 条 `SyncLineupNotify`**（1 条上半队 + 3 条下半队），hsr-local 只发 1 条。

## 10. 抓包时踩到的两个实现坑（已修）

- **EC2B 不是"直接拿 16 字节算种子"**：`Ec2b` 构造时会先 `KeyScramble(key)`（AES 逆轮 + 固定
  176 字节轮密钥 + `keyXorTable`），再算 MT19937 种子。漏了这步 → 4096 字节掩码全错，
  表现为"KCP 能拆、帧全是 8.0 熵的密文"。修法见 `hsrwire._scramble_key`，用 .NET 编译原实现逐值比对过。
- **`secret_key_seed` 的字段号会漂**：4.6.54 的 proto 里是 **field 9**（不是 Danheng 那版的 11），
  所以 `relay.py` 改成"token 回包里所有 varint 都当候选，用下一帧能不能解开投票"，
  `redecode.py` 用同一套逻辑离线重解。

## 11. 落地：`[endgame] advance = "official"`（2026-11-12 晚）

§9 的 7 处差异逐条对应：

| # | 差异 | 实现 |
|---|---|---|
| 1 | 不重建场景 | 返回的 `Transition` 只有 `before`，不发 `SyncServerSceneChangeNotify` / `EnterSceneByServerScNotify` |
| 2 | 先删上半的怪 | `group_refresh_notify(remove=…, refresh_type=3)`，删 `scene.extra_groups` 里的全部实体（官方那一组只有怪） |
| 3 | 换角色实体 | 同一个 `GroupRefreshInfo` 里先 `delete_entity` 再 `add_entity`；`scene.avatar_base` 每半场 +4（官方 1048579-82 → 1048593-96 的同类做法） |
| 4 | 顺序 | 删旧怪 → 换角色 → 3×`SyncLineupNotify` → `ChallengeLineupNotify` → 声明新组 → 移动通知 |
| 5 | 结果包最后 | `battle.py::_advance_phase` 先发 `transition.before` 再发 `rsp`；`official` 把 10 个包全塞进 `before`，`after` 为空 |
| 6 | `refresh_type=3` | `scene.GROUP_REFRESH_REFRESH`（客户端枚举 `AFIBFMAFNCC`） |
| 7 | 4 条阵容包 | 1 条上半队（`LineupChallenge`）+ 3 条下半队（`LineupChallenge2`） |

配套改动：

- `scene.avatar_base`（`SceneState` 字段，默认 1）：`avatar_entities` 用
  `avatar_base + slot` 当 entity id。
- `scene.leader_entity_id(session)`：`SceneInfo.leader_entity_id`、`move_notify`、
  `SceneEntityMoveCsReq` 的队长判定都改成跟着基座走，换半场后 leader 不会指向已删实体。
- `declared_group_notify(..., state=…)`：官方的 `group_info.state` 留空（0），
  老 `declare` 路径仍用 1。
- `move_notify(..., entity_id=…)`：官方那条 `SceneEntityMoveScNotify` 不带 entity_id。

两处**故意**不照抄：

1. **两条 `SyncEntityBuffChangeListScNotify`（#593/#596）**：动的是官方本局专用的挑战
   buff 实体（6291457 / 6291458）和遗器派生的 buff id（1000120/1000121/150202/140703/
   150602/3030149）。私服没有这些实体，照抄只会给不存在的 entity 发 remove。
2. **角色实体 id**：官方那串是它的全局实体计数器，私服场上实体是 1..4；用自己的
   `avatar_base` 换一批新 id，语义一致（删旧加新，不复用 id）。
