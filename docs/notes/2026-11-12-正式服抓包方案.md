> **状态**：现行·方案　**适用版本**：正式服（目标 4.7.0 CN，build 17108910）　**最后修订**：2026-11-12
>
> 用途：把私服里「服务端能对齐的都对齐了、剩下只能靠官方行为回答」的问题（当前是
> 混沌回忆下半战斗卡进场动画）交给**同一版本正式服的真实包序**来回答。
> 工具不在仓库里：`E:\LCXS\tools\official\`。

## 0. 一句话现状

抓包链路**已经做完并离线验证**（加解密、中继、报告全绿 13 个用例），但**还没有真机数据**：
正式服此刻对 `query_gateway` 一律回 `retcode=3 / "client version not match"` + 维护公告，
既不给 `ip/port` 也不给 `client_secret_key`（2026-11-12 17:2x 实测）。等开服 + 真实账号即可跑。

## 1. 为什么不用网卡嗅探

1. 本机没有 Npcap，装驱动要管理员 + 可能重启；
2. 更关键：**官方 UDP 载荷是加密的**，嗅探下来也是乱码；
3. 中继方案不要驱动、不要管理员，抓到的还是**解密后**的帧。

## 2. 三条链路（与私服同构，只是终点换成官方）

```text
StarRail.exe --(系统代理 :9978)--> firefly-go-proxy
     firefly 用自带 CA 终止 TLS，把登录域名反代到 127.0.0.1:21000（保留 Host 头）
       --> mirror.py :21000
             逐字节转发到 https://<Host><path>（官方 dispatch / SDK 原样请求原样返回）
             唯一改写：/query_gateway 的 GateServer.ip/port -> 127.0.0.1:23301
             顺手落盘 client_secret_key（EC2B）
StarRail.exe --(UDP :23301)--> relay.py --(UDP)--> 官方游戏服
             透明中继；实时解密并写 capture.bin
```

差别只在两点：私服自己造登录响应，这里**透传官方**；私服明文，这里**要先解密**。

## 3. 加密（这是抓包工作的主体）

依据 DanhengServer `Common/Util/Security/{Ec2b,MT19937,Crypto}.cs`，并用 .NET 10 编译原实现
逐值交叉验证（`tools/official/_csvec/`）。

| 阶段 | XOR 密钥 | 来源 |
|---|---|---|
| 连接开始 → `PlayerGetTokenScRsp`（cmd 71） | EC2B 静态密钥 4096B | `query_gateway` 的 `GateServer.client_secret_key`（field 403 = base64 的 2076B EC2B） |
| 之后全部 | MT19937(`secret_key_seed`) 4096B | cmd 71 body 的 field 11（u64） |

- XOR 是 4096 字节循环掩码，**整帧**（含 `9D74C714` 魔数）参与，每帧从 key[0] 重来；
- 两把钥匙的 u64 字节序不同：EC2B 小端、seed 大端（原实现如此，别「修」）；
- relay 每帧先试明文再试两把钥匙，假设错只会退化成「未解密」，不会静默写坏。

## 5. 怎么跑（需要人做三步）

1. `powershell -NoProfile -ExecutionPolicy Bypass -File E:\LCXS\tools\official\run.ps1`
2. UAC 点「是」（firefly 要装自己的 CA + 设系统代理），然后在客户端里用**真实账号**登录；
3. 进混沌回忆打一层，**上半打完进下半**，等它结算，回车停。

## 6. 判据：拿到包之后先看这四件事

1. 上半结束后客户端有没有发 `EnterChallengeNextPhaseCsReq`（1715）——私服从没见过这条；
2. 官方有没有让客户端**再发一次** `StartChallengeCsReq`（pearl-sr 路线），还是纯服务端推；
3. `PVEBattleResultCsReq` 之后到下半第一帧之间，服务端发了哪几条 Notify（顺序即契约）；
4. 下半那场 `PVEBattleResultCsReq` 的 `stt` 里 `turns` 是否 ≥1（私服恒为 0）。

## 7. 已知坑

- **维护期抓不到**：`query_gateway` 回 `retcode=3 / "client version not match"` 时没有 ip/port，
  mirror 会打 `gateway NOT rewritten: no ip/port in GateServer`——这就是「等开服」的信号；
- **签名**：不带客户端自己的签名参数直接 GET `query_dispatch` 会回 `{"retcode":3}`，
  所以 mirror 只透传、不自己拼参数；
- **firefly 要 UAC**：跑完确认系统代理已恢复（否则浏览器/其他程序会指到 9978）；
- 源 IP 仍是本机公网出口，与直连一致，不是代理 IP。
