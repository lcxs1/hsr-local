## 1. 现在的代码在做什么（接手先看这一节）

- 一个挑战 = `phases: list[Phase]`（`node + team + lineup_type`），`index` = 当前半场。
  核心在 [services/challenge.py](../../hsr/game/services/challenge.py)（`enter` / `enter_tierce` /
  `start_direct` / `advance` / `apply_result_stats` / `battle_info` / `cur_challenge` / `lineups`）。
- **阶段切换 `[endgame] advance = "sync"`（默认，真机可用）**：
  1. `ChallengeLineupNotify(LineupChallenge2)` + `SyncLineupNotify(下半阵容)` —— 结果包**之前**；
  2. `PVEBattleResultScRsp`；
  3. `SyncServerSceneChangeNotify`（客户端据此整套重进场景，会重载 stage）；
  4. `EnterSceneByServerScNotify`（整份新 `SceneInfo`：角色组 = 下半队伍，`entity_group_list`
     里声明 node2 的迷宫组）—— 结果包**之后**。
  一条 `SceneGroupRefreshScNotify` 都不发。
- 其它 `advance` 值都是 A/B 探针，**已知结论**见 §3 表（`declare` / `inplace` / `scene` / `client`）。
- 挑战中客户端重进同一入口时，`on_enter_scene` 回**当前半场**的挑战场景（不然会被野外场景冲掉）。
- 退出挑战发 `ChallengeLineupNotify(LineupNone)` + `SyncLineupNotify` 回原场景；
  `CurChallenge.round_count` / `dead_avatar_num` 按 `stt` 累计，轮次预算跨半场共用。
- 大厅：`[endgame] lobby_teleport = "scene"`（默认，照常切）；`ignore` 是“宁可不进大厅也别卡”的开关。
  入口没有水晶道具时会在出生点合成三块（`scene_service.spawn_crystals`）。
- 取证脚本 [scripts/game_test.ps1](../../scripts/game_test.ps1)：事件驱动截图 + 全程镜像 `Player.log`
  + 报告 A–H；**改完必须补 UTF-8 BOM**（PS 5.1），否则中文乱码解析失败。

**现象（用户原话）**：「进入了下半场景，可以看到 NPC，攻击了，正常来说会近战，但卡在了进战斗的动画

**已做的实验（都失败，别再重复）**：

| 实验 | 运行 | 结果 | 说明 |
|---|---|---|---|
| `sync` 原样 | `test-20261111-232502` | ❌ | cast 后 4 秒画面全黑（`-48/-50/-51/-52` 都 ~399 KB），`turns=0` |

下半那场战斗就起不来。所以变量要切到**战斗本身**。

**下一步（已实现，等真机）：`GET /debug/challenge?id=5501&second=1`**
（`challenge_service.start_direct(session, id, second=True)`，提交 `e372f2b`）

## 5. 日志怎么看（不用重跑游戏）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\game_test.ps1 -AnalyseOnly .\logs\test\<run>.server.log
```

自动读同目录 `<run>.client.log` / `<run>.packets.log`，重写 `<run>.report.md`
（A 结论 · B 事件时间线 · C 请求序列（C2=advance 之后）· D 下半窗口客户端日志 · E 异常去重 ·
F 截图 · G 服务端尾部 · H 手动确认）。

| 目标 | 怎么查 |
|---|---|
| 服务端阶段机 | server.log 搜 `challenge advance` / `challenge battle result` / `challenge settle` / `battle stats` |
| 有没有真的打 | server.log 的 `battle stats: ... turns=...`（**下半 `turns=0` 就是没打**） |
| 客户端组刷新 NRE | client.log 搜 `Already Exists` / `_ActiveServerHoyoGroup` / `RefreshServerHoyoGroup` |
| 大厅坏 NPC | client.log 搜 `MapNPC:.*FAILED` / `MapNpcDef` |
| 客户端重载 stage | client.log 搜 `AdventurePhase:_EnterStep2` / `VFS Path1 .*Stages` / `Unloading \d+ unused` |
| 黑屏判定 | 截图文件大小：正常 3 MB+，**全黑只有 ~400 KB**（这一晚最快的判据） |

注意：客户端 `Player.log` **对战斗场景失败一句都不打**（没有 `battleArea` 之类的行），所以别指望
从客户端日志里看到“为什么战斗起不来”，只能靠服务端行为 + 截图。

## 8. 这一晚的教训（省下下一次的时间）

- 4.7.0 的 `SceneGroupRefreshScNotify`：`LOADED` = 激活组，**不能**用来卸载；卸载只能 `UNLOAD`（`unload_old_group`）。
- 更根本：**4.7.0 不认“中途凭空多出来的 server group”**。组必须在 `SceneInfo.entity_group_list` 里声明过。
- `GroupRefreshInfo.group_info` 声明出来的组，客户端**不给可攻击的怪**（`declare` 实验，23:46）——
  所以群组切换必须走 `SceneInfo`。
- 服务端发“卸载/重进”之前先想清楚客户端是否真的需要它。
- 大厅传送忽略 = 入口也没了；入口在大厅 UI 里，不能靠“不切场景”绕过。
- 多轮尝试的日志混在一起时，统计要按“一轮挑战”切片（advance → 下次 start/leave），否则会串轮。
- 截图大小是最快的黑屏判据；`battle stats.turns` 是最快的“打没打”判据。
- 改 `scripts/*.ps1` 之后要补 UTF-8 BOM，否则 PS 5.1 解析失败。
