## 1. 现在的代码在做什么（重构后的模型）

- 一个挑战 = `phases: list[Phase]`（`node + team + lineup_type`），`index` 是当前半场。
  见 [services/challenge.py](../../hsr/game/services/challenge.py)。
- 上半 → 下半（`[endgame] advance = "sync"`，默认，参考 LunarCore `advanceStage`）：
  1. `ChallengeLineupNotify(LineupChallenge2)` + `SyncLineupNotify(下半阵容)` —— 结果包**之前**发；
  2. `PVEBattleResultScRsp`；
  3. `SyncServerSceneChangeNotify` —— 告诉客户端“服务器场景变了”，它会整套重进；
  4. `EnterSceneByServerScNotify`（整份新 `SceneInfo`：角色组 = 下半队伍，
     `entity_group_list` 里声明 node2 的迷宫组）—— 结果包**之后**。
  **一条 `SceneGroupRefreshScNotify` 都不发**（`inplace` / `scene` / `client` 只留作 A/B）。
- 额外阵容 `LineupInfo.index = 0`，种类只看 `extra_lineup_type`；退出挑战发
  `ChallengeLineupNotify(LineupNone)` + `SyncLineupNotify`；`CurChallenge.round_count` /
  `dead_avatar_num` 按战斗结果累计，轮次预算跨半场共用。
- `[endgame] lobby_teleport = "scene"`（默认）：大厅传送照常切场景；`ignore` 只作为“宁可不进大厅也别卡”的开关。
  大厅入口没有水晶道具时会在出生点合成三块水晶（`scene_service.spawn_crystals`）。

**下半黑屏的排查顺序**（一次只改一个）：

> 用户对下半那场的原话（2026-11-11 23:39）：**「进入了下半场景，可以看到 NPC，攻击了，
> 正常来说会近战，但卡在了进战斗的动画（类似之前截图的『弱点』），几秒后直接结算了」**。
> 也就是：场景和怪都正常，**卡在"进战斗"的进场动画**，客户端自己超时后报 WIN → 结算页。

工作假设：客户端被 `SyncServerSceneChangeNotify` 逼着重载了整个 stage
（`AdventurePhase._EnterStep2` → `Map._LoadStage` 996256495 + `Unloading N unused Assets`），

1. **先做零改动的对照实验**：进下半后**等 20 秒**（等读条和资源加载完全结束）再走到怪旁边按 F。
   还卡 → 不是加载竞态，走第 2 条；不卡 → 竞态成立，走第 3 条；
2. **换 `advance = "declare"`**（已实现，改 `config.toml` 一行）：不推场景、不重载 stage，
   改用 `GroupRefreshInfo.group_info`（和 `SceneInfo.entity_group_list` 同一个 message）
   原地**声明**下半的迷宫组。这条如果成立，下半就和上半走完全一样的路径；
3. 若 `declare` 也不对：把 `advance` 改回 `"sync"`，再试「结果包之前就推场景」
   （LunarCore 的顺序是 `onBattleEnd` 里先推 `EnterSceneByServerScNotify` 再回 `PVEBattleResultScRsp`，
   我们现在是之后推）；
4. 数据核对（已做）：`data/endgame.json` 的 `stages[30126012]` 与 pearl-sr `StageConfig.json` 的
   `MonsterList` 完全一致（`[[8012010, 2013020, 8012010], [2013020, 2013020]]`），

## 7. 复盘：这一晚踩过的坑（新坑，已写进 guide/03）

- 4.7.0 的 `SceneGroupRefreshScNotify`：`LOADED` = 激活组，**不能**用来卸载；卸载只能 `UNLOAD`。
- 更根本的一条：**4.7.0 不认“中途凭空多出来的 server group”**。组必须在
  `SceneInfo.entity_group_list` 里声明过；`refresh_entity` 只对已存在的组有意义。所以换半场的
  正解是把新场景整份推过去（`SyncServerSceneChangeNotify` + `EnterSceneByServerScNotify`），
  而不是 patch 组。
- 服务端发“卸载”之前先想清楚客户端是否真的需要它；旧组留着不影响下半（怪已死）。
- 大厅传送忽略 = 入口也没了；入口在大厅 UI 里，不能靠“不切场景”绕过。
- 多轮尝试的日志混在一起时，统计要按“一轮挑战”切片（advance → 下次 start/leave），否则 cast/重打判断会串轮。
