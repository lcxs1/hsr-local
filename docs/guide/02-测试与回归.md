## 3. 跑脚本

先**完全关闭游戏**（任务管理器里没有 `StarRail.exe`），然后：

```powershell
cd E:\LCXS\run\hsr-local
# 默认：混沌回忆阶段切换取证（4.7.0），脚本起服务端+代理+游戏（UAC 点“是”）
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\game_test.ps1
```

脚本按 `-Scenario` 分两种：

**challenge（默认，2026-11-11 起的重点）**——验证「上半 → 换组 → 下半 → 结算 → 退出」：

1. 检查 21000/23301 端口，用 `--profile 4.7.0` 起服务端；
2. 起 firefly 代理 + 游戏（**UAC 点“是”**）；
3. 等登录后进入**事件循环**：每秒扫服务端日志与 `packets.log`，把
   `start challenge / battle info / cast / battle result / advance / settle / leave`
   打进时间线并实时打印；
4. **事件驱动截图**：开始挑战、每次战斗包、换组后 +0/+6/+14/+25 秒（下半黑屏就在这段）、
   结算、退出各拍一张；
5. 全程**镜像客户端 `Player.log`**（游戏每次启动会覆盖它，所以边跑边存）；
6. 按 **Enter** 结束（或 `-MaxMinutes` 到点）→ 写
   `logs\test\<run>.report.md` + `<run>.client.log` + `<run>.packets.log`。

报告里 A 段自动判定：上半开打/胜利、阶段切换、下半开打/胜利、结算、退出、
**下半的客户端反应（`SceneCastSkillCsReq` / `QuitBattleCsReq` 次数）**、客户端异常；
B 是服务端事件时间线，C 是挑战请求序列，D 是下半窗口的客户端日志，E 是异常去重，
G 是服务端日志尾部。

**core**——旧的通用回归（凝滞虚影三连战 / 换队 / 命途 / 换肤 / 指南），
截图按 `-ShotPlan` 定时拍，报告按请求计数：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\game_test.ps1 -Scenario core -Client 4.6.54
```

常用参数：

| 参数 | 作用 |
|---|---|
| `-Scenario challenge\|core` | 选场景（默认 challenge） |
| `-Client 4.7.0\|4.6.54` | 客户端版本（exe / Player.log / `--profile`） |
| `-NoLaunch` | 代理/游戏自己启动，脚本只起服务端 |
| `-NoGame` | 只查看步骤，不启动任何东西 |
| `-MaxMinutes 25` | 兜底自动收工 |
| `-StopAfterSettle` | 结算后 45 秒无新挑战包自动收工 |
| `-AnalyseOnly <run>.server.log` | 不启动任何东西，把已落盘的日志重新分析成报告 |
| `-ShotPlan 10,60,120,180` | 只影响 `-Scenario core` 的定时截图 |
| `-KeepServer` / `-KeepProxy` | 结束后保留服务端/代理 |
| `-PatchPrefs` | 对照客户端 prefs（登录后会被覆盖，通常不需要） |

> `.ps1` 改完必须是 **UTF-8 with BOM**（PS 5.1 读无 BOM 的中文脚本会解析错乱）。

## 4. 手动测试步骤

**challenge 场景（脚本事件循环中）：**

1. 登录后走 **星际和平指南 → 忘却之庭 → 混沌回忆**；
   **不要点任何「传送 / 前往」**：4.7.0 一加载忘却之庭大厅 floor 就会挂在
   `[MapNPC:227-400001]`（`MapNpcDef.get_ConfigEntityPath` NRE → SDK 弹框 → 会话关闭），
   这是客户端自己的 floor 配置问题，服务端补不了。服务端默认
   （`[endgame] lobby_teleport = "auto"`）会把这种传送**忽略**掉（你只会看到场景重载一次），
   但别去点它；面板路线是纯 UI，不需要大厅；
2. 选 **第 1 层**（第 12 层是 4.7 的星启 3 节点模式，另算），编队界面两队都放满 → 开始挑战；
3. **上半**：走到怪旁边按 F 开打，打完**不要动**，等 20 秒看会不会自动进下半；
4. **下半**：能打就打（确认是不是第二队）；黑屏/卡住就等 30 秒，别退；
5. 结算页看星数/剩余轮次，然后**退出挑战**回世界；
6. 再进一次、再打第 1 层（验证退出后重新进不污染）；
7. 回 PowerShell 按 **Enter**（或直接 `-MaxMinutes` 到点自动收）。

**core 场景（旧步骤）：**

1. **出生点**：人物是否站在凝滞虚影上；退出重登一次，确认还是同一位置。
2. **战斗 + 再来一次**：按 F → 选关卡 → 打完结算 → 点一次「再来一次」，
   确认直接进第二场；再打一场，确认能连续循环。有「快速开始」也点一次。
3. **主角在队换人**：把主角放进队伍，换掉一个队友再换回来；确认队伍和场景
   都变化，重登后保持。
4. **命途切换**：切主角/三月七命途；确认立绘、技能、队伍同步变化；重登后保持。
   日志应出现 `avatar path changed: base=... path=...`。
5. **皮肤切换**：给三月七穿 `1100101`，确认立绘、头像和队伍模型变化；再点脱下，
   重登后保持。日志应出现 `avatar skin changed: avatar=1001 skin=1100101`。
6. **指南提示**：进世界后先别按键，看是否**没有**「G 多层韧性」/「欢愉命途」。
   如果还出现，按 G → 关闭 → 再按 G……记录第几轮消失、重登是否回来。
7. **未知命令**：正常关游戏/停服务端后，服务端 stdout 末尾会打印
   `unknown commands: N distinct / M packets`；报告里也会显示「未知命令」数量。
8. **秘技点**：连按秘技 6 次以上。每次客户端先发 1498，服务端补点靠
   `SyncLineupNotify`；`unlimited` 下始终满，`refill` 约 5 秒 1 点，`normal` 5 次耗尽。

完成后回 PowerShell 按 **Enter**。

## 5. 回传什么、报告怎么看

回传（2026-11-11 起）：

- `logs\test\<run>.report.md`（A 段结论 + 时间线 + 挑战请求序列 + 下半窗口客户端日志）
- `logs\test\<run>.client.log`（本次运行的客户端日志镜像，游戏每次启动会覆盖原文件）
- `logs\test\<run>.packets.log`（本次运行的请求序列）
- 截图按需（`<run>-NN-<事件>.png`，事件名见报告 F 段）
- 一句主观结果：上半/下半画面、有没有自动进下半、结算页、退出后回哪。

报告自动带（challenge 场景）：

```text
A. 结论摘要：开始挑战 / 上半开打 / 上半胜利 / 阶段切换 / 下半开打 / 下半胜利 /
            结算 notify / 退出挑战 / 下半的客户端反应（cast、QuitBattle 次数）/ 客户端异常行
B. 事件时间线（服务端日志匹配行，带毫秒时间戳）
C. 挑战请求序列（从 StartChallenge 到 LeaveChallenge；C2 是 advance 之后的下半窗口）
D. 下半窗口的客户端日志（advance 行号 → settle 行号，只留关键字行）
E. 客户端异常去重
F. 截图清单
G. 服务端日志尾部 40 行
H. 手动确认清单（回传时填一下）
```

旧 `core` 场景的报告仍是请求计数 + `Player.log` 末尾异常 + 「闭环检查」。

关键细节仍可直接看 `logs\packets.log`：

```text
-> ReplaceLineupCsReq ...
-> SetAvatarPathCsReq ...
avatar path changed: base=8001 path=8003
```

想重新分析已经落盘的日志（不启动服务端/游戏）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\game_test.ps1 -AnalyseOnly .\logs\test\<run>.server.log
```

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| 21000/23301 被占用 | 关掉旧服务端/测试器 |
| 检测到 StarRail.exe | 先完全退出游戏 |
| 一直等登录 | 代理没设系统代理，或 firefly 没拦截登录域名 |
| 截图全黑 | 游戏改无边框窗口 |
| 结算页「再来一次」没反应 | 看服务端是否每场分配新 `battle_id`；日志 `battle info: id=1/2/3...` |
| `--strict` 报 calyx cocoon 缺失 | `world.json.calyx_cocoon_id` 必须在 `battle.json.cocoon_stage_map` 有映射 |
| 快速开始没反应 | 看 `packets.log` 是否有 `QuickStartCocoonStageCsReq`；handler 与 Start 共用逻辑 |
| 皮肤页没有条目 | 看 `GetAvatarDataScRsp.skin_list` 是否为空；检查 `data/skins.json` / `paths.skins` |
| 穿皮肤 retcode=1 | `skin_id` 与角色不匹配；对照 `data/skins.json` 的 `avatar_id` |
| 主角在队时换人无效 | 看 `LineupAvatar.id` 是否用了形态 id；`ReplaceLineup` 是否归一化 |
| 命途按钮不出现/点了没包 | 看 `packets.log` 是否有 `SetAvatarPathCsReq`；先查 `avatar_path_data_info_list` 是否只发同性别形态 |
| 报告里 `FinishTutorialGuide` 为 0 | 正常：客户端不再发完成指南请求，`UnlockTutorialGuideCsReq` 也应为 0 |
| 秘技放几次就灰了 | 确认 `[gameplay].technique_points` 不是 `normal`；每次 1498 之后应有 `sync=True` |
| 秘技点 `/5` 一直是 0 | 检查 `LineupInfo.mp`：`build_lineup()` 会带 `technique_points_max`，`unlimited` 下恒满 |
| 指导「传送」没反应 | 看 `packets.log` 是否有 `enter scene: entry=100000104`；没有则是 handler/场景数据问题 |
| 传送后加载条卡死 | 先看 `Player.log` 是否 `MapNPC:227-400001` NRE（客户端资源问题，重试）；同时检查组统计 oneof 是否填满 |
| 挑战打完怪重生、不结算 | `ChallengeSettleNotify` 没发或字段不全；看日志是否有 `challenge battle result` |
| 结算后回初始世界而不是大厅 | `LeaveChallenge` 没回到进入前场景；看 `leave challenge` 日志 |
| 挑战面板显示 45/45 满进度 | 正常：`star=7` / `taken_reward=42` 抄 pearl，不是真实进度 |

挑战链的根因与修复细节见 [../design/03-终局玩法](../design/03-终局玩法.md) §5。
