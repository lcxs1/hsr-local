## 3. 踩过的坑（务必别再踩）

1. **protobuf 消息字段不能赋值**：`msg.field = Sub()` 抛 `AttributeError`，要用
   `msg.field.CopyFrom(Sub())`（Lua 控制台曾因此坏了很久）。
2. **指南组 id/type**：`GetTutorialGuideScRsp` 必须返回 **GroupID（如 1101）+ `type=0`**；
   单条 guide id（110101）或 `type=1` 都会让客户端每次登录重解锁 57 组，出现
   「位面规则」「欢愉命途」弹窗和「G 多层韧性」提示。`data/tutorials.json` 864 组必须全 0。
3. **客户端 prefs 不可靠**：`User_<uid>_UnlockedTutorialGuides` / `FinishedTutorials`
   每次登录会被客户端重写；不要用注册表去“修”提示/红点。
4. **PowerShell 脚本必须 UTF-8 BOM**：PS5.1 读无 BOM 的中文 `.ps1` 会解析错乱；
   编辑后检查头三字节 `EF BB BF`。
5. **游戏是管理员进程**：普通权限 → 鼠标注入被 UIPI 拦（`SetCursorPos` 失败），键盘可用；
   截图前要 `SetProcessDPIAware()`，否则坐标是 1720×1070 而非 2560×1600。
   真机测试不要自动点鼠标。
6. **系统代理**：firefly 退出/被杀不会还原 `ProxyEnable`，每次测试后置 0。
7. **单人会话**：新握手会替换旧会话（`single_client`），换窗口重登即可。
8. **登录慢**：客户端启动后约 30–45 秒才进世界，自动化要等够（`game_test.ps1` 默认 240s）。
9. **字段名陷阱**：`MazeGroup` 没有 `state` 字段；`Relic` 用 `dress_avatar_id`；
   `AvatarPathData.ExRankList` 首字母大写（protoc 原样保留）。
10. **`unknown_mode`** 默认 `empty_rsp`；试 `silent` 后记得改回。
11. **战斗 `battle_id` 不能复用**：结算后仍回同一个 id，客户端会停在结算页；
    每场 `StartCocoonStage` 必须分配新 id（`BattleData.next_battle_id`）。
12. **阵容 id 有两套语义**：存档用基座（8001/1001），`LineupAvatar.id` 用形态（8003/1224）。
    `ReplaceLineup` 要接受两种并归一化，否则主角在队时换人失效。
13. **主角命途与性别**：`8001..8010` 奇男偶女；`player.gender` 是权威开关，
    只下发同性别形态，`tb_multi_path` 不一致时自动校正。
14. **秘技点只能靠 `SyncLineupNotify` 补**：`SceneCastSkillMpUpdateScNotify`(1448)
    只能扣不能加（真机 A/B 验证）；`LineupInfo.mp/max_mp` 才是点数载体。
15. **挑战链三个必做点**（详见 [../design/03-终局玩法](../design/03-终局玩法.md) §5）：
    `GetChallengeGroupStatisticsScRsp` 必须填满 oneof（否则客户端 NRE、传送卡死）；
    战斗结束必须发 `ChallengeSettleNotify`；`LeaveChallenge` 要回**进入前的场景**。
16. **freesr 热更新**：网页「连接 PS」首次是探活（无 `data`），必须回 200；
    网页没“加载数据”时推空遗器会被 400 拒绝；文件用 `utf-8-sig` 读；
    `apply()` 后立刻更新 `runtime.freesr_signature`，否则 watcher 会回环重复推送；
    `battle_config` 只落盘，**没有**参与战斗。
17. **版本升级时不要在文档里照抄旧数字**：先跑 `scripts\check.ps1`，
    再按 [docs/README §3](../README.md#3-关键数字唯一事实源) 更新。
18. **CN 客户端的 `Player.log` 不在旧路径**：4.7.0 CN 客户端写
    `%USERPROFILE%\AppData\LocalLow\miHoYo\崩坏：星穹铁道\Player.log`；
    `Cognosphere\Star Rail` 是旧 CBT 客户端的。脚本按客户端分开取。
19. **hotfix 的 URL 必须与客户端安装时一致**：客户端比对的是安装时那份资源清单，
    拿旧版本的 CDN 地址会让它重新下载（写进 `StarRail_Data\Persistent`），
    空地址则直接「资源下载失败」。本地清单回放是可行的绕行，见
    [../reference/05-4.7.0兼容性实测](../reference/05-4.7.0兼容性实测.md) §3。
20. **4.7 客户端对“空回包”更敏感**：`GetArchiveDataScRsp` 回空 body 会让
    `AvatarArchiveData.Sync` 抛 NRE 并停止发包（心跳 15 秒后断会话）。
    给这类“子消息字段”的响应补一个空但存在的子消息，别只回空 body。
21. **Clash Verge 的 TUN 会抢域名解析**：TUN 开着时游戏域名解析成 `198.18.x.x`（fake-ip），
    客户端可能绕过 firefly 直连；真机测试前关 TUN，测完再开。判断方法：`Resolve-DnsName <域名>` 返回 `198.18.*` 就是开着。
22. **4.7.0 必须开 `features.local_cdn`**：`data/hotfix.json` 的 `CNPRODWin4.7.0` 只有
    `LOCAL_CDN/...` 占位符，关掉回放时客户端停在「资源下载失败」；`--profile 4.7.0`
    不会自动打开它。回放读取 `[paths].client_dir`（默认 `StarRail_CN_4.7.0`），
    `client_dir` 写错时启动日志会报 `local CDN: ... has no StarRail_Data/`。
23. **回放的清单必须“一行一个 JSON（CRLF）”**：用 `..` 拼成一行能过预登录校验，但进世界前的
    版本更新会用严格 JSON 解析整份清单，报 `Additional text ... ..`，随后弹「任务资源管理
    （27987.72MB）」并停心跳。改回 CRLF 即恢复（见 [../reference/05](../reference/05-4.7.0兼容性实测.md) §3.1）；
    重试前删掉客户端写下的 `Persistent\DesignData\Windows\M_Design_ArchiveV_cache.bytes`。
24. **改 `scripts\*.ps1` 不要丢 UTF-8 BOM**：这些脚本含中文，Windows PowerShell 5.1 没有 BOM 时
    按 ANSI 读，字符串截断后整脚本报 `Unexpected token`。用编辑器改完确认首字节是 `EF BB BF`。
25. **挑战战斗的 `battle_id` 必须幂等**：客户端在 arena 加载期间会反复发 `SceneCastSkill`
    （真机一局 8 次），每次都给新 id 会让服务端的"当前战斗"跑到前面，`PVEBattleResult`
    回的是旧 id → 判定不属于当前战斗 → **不发 `ChallengeSettleNotify`**，于是回场景、
    怪重生、无限循环。`battle_info()` 复用已激活战斗，`ChallengeState.battle_ids` 记录
    本次挑战分配过的所有 id，结算按集合判定（修于 2026-11-11，待真机复测）。
26. **忘却之庭大厅在 plane 10000**：指导「传送」`entry=100000104` → `plane=10000/floor=10000000`
    （列车车厢）。这份数据不在挑战 arena（301xx）里，必须单独导出到 `data/endgame.json`
    的 `lobby` 段；缺了就只能按普通世界装配，客户端只显示角色组 + 凝滞虚影组两个"默认关卡组"。
27. **两段式挑战不是"赢了就结算"**：MOC/PF/AS 的 `StageNum=2` 有 node2（下半），
    上半打完要加载下半场景 + `ChallengeLineupNotify(LineupChallenge2)`，下半打完才
    `ChallengeSettleNotify`；否则客户端拿到一次整局结算，看不到「前往下半」。
28. **`game_test.ps1 -ShotPlan 15,45` 的逗号会被终端吃掉**：实际变成 `+1545 秒`
    （2026-11-11 踩到，报告里只有 1 张迟到截图）。用空格分隔（`-ShotPlan 15 45`）或默认值。
29. **上下半是两套队伍**：`StartChallengeCsReq` 同时带 `avatar_lineup_first` 和
    `avatar_lineup_second`（点水晶后的队伍配置界面）。只保存第一套，下半会继续用上半的队伍。
    另外客户端只带第二套重发 `StartChallengeCsReq` 时是"进下半"，不能当成新挑战清状态
    （pearl-sr `onStartChallenge` 同分支）。
30. **同一个 entry 再点「传送」不能是空操作**：`on_enter_scene` 里 `entry_id == state.entry_id`
    时也要重新装配场景并下发，否则按钮看着"失效"（2026-11-11 真机）。
31. **退出挑战要回世界，不要留在大厅**：大厅（plane 10000 列车车厢）是在 `EnterSceneCsReq`
    里切过去的，`LeaveChallenge` 只记大厅会把玩家困在车厢里；进大厅时把来之前的场景存到
    `session.lobby_return`，退出时优先回那里（pearl-sr 的 `onLeaveChallenge` 也是直接回世界场景）。
32. **`SceneBattleInfo` 字段 7 是 `monster_wave_length`**（4.6.54 descriptor 混淆成 `JAOIOKBBMFC`）；
    pearl-sr 每次都按波次数填。不填时多波次战斗可能预载不到波次数据，表现为战斗场景初始化
    失败（客户端 `Player.log` 报 `获取BattleArea的编辑器配置信息battleAreaDef失败`、黑屏）。
33. **忘却之庭的关卡组卡片来自 `challenge_group_list`**，不是 `challenge_list`：只发后者时
    客户端只剩零星默认组（2026-11-11 真机"混沌回忆关卡组页面丢失"）。每个 group 发一条
    `ChallengeGroup(group_id, taken_stars_count_reward=0)`。
